## B. 「这功能为什么存在」—— 已查明来历，等决策

### B1. 审批框（权限请求卡片）**[已查明]**

**它是什么**：Agent 执行过程中要改文件、跑命令时会请求授权。这个框让你直接在灵动岛上
批准或拒绝，不用切回 Agent 的终端窗口。四个按钮分别是：拒绝 / 允许一次 /
始终允许（本次会话内该类操作不再问）/ 自动批准（后续全部自动放行）。

它不是装饰，按钮真的会把决定回传给 Agent（`respondPermission` → Hook 通道）。

**来历**：最初的 PRD 第 23 行写的是「**知道**哪些 Agent 正在等待权限或用户输入」——
要求的是**可见性**，不是在岛上直接批准。直接批准的交互是上游 AgentBro 带来的能力，
随 fork 保留至今，**确实没有被明确要求过**。

**存在必要性的论证**：
- 支持保留：它正面解决 PRD 里「不用切窗口」这个核心诉求。只显示「某某在等权限」
  而必须切窗口去点同意，等于把问题解决了一半。
- 支持去掉：它是弹出式的，会遮挡内容；而且截图里 Agent 名显示为 `Unknown`，
  说明会话标题没取到，观感像是坏的。

**建议**：不要整体删除，先修两个具体问题——① `Unknown` 是缺陷，应显示真实会话名；
② 增加一个开关，让用户选择「只提示、点击跳转到终端处理」还是「就地批准」。
**待维护者确认这个方向。**

## C. Bug

### C1. 设置窗口最小化后无法恢复 **[已查明根因]**

**复现**：最小化设置面板后再也打不开。

**根因**（`src-tauri/src/lib.rs`）：
1. 第 2229 行 `window.set_skip_taskbar(true)` —— 设置窗口被刻意排除在 Windows
   任务栏之外，所以最小化后任务栏上没有可点的按钮。
2. `show_settings_window` 只调用了 `show()` 和 `set_focus()`，**全仓库没有任何
   `unminimize()` 或 `is_minimized()` 调用**。在 Windows 上对一个已最小化的窗口
   调 `show()` 不会还原它。

两者叠加 → 窗口既不在任务栏、也无法通过再次「打开设置」还原。

**修法**：`show_settings_window` 中在 `show()` 之前判断并调用 `unminimize()`。
修完需要真机验证，单元测试覆盖不到窗口状态。

## E. Skill 管理

### E1. 「分发」语义不对 **[待决策]**

维护者观点：某个 Agent 拥有一些 Skill，那是它的**私有**，不是你主动「分发」过去的。
按「分发」的说法，会让人以为中心库里的 Skill 默认全部对所有 Agent 生效。

**当前实际行为**（截图中的提示文案已说明）：中心库 Skill 默认处于**未分类**状态，
不会自动作用于所有 Agent，需要手动分发。所以行为本身是对的，**问题出在命名**。

**待决策**：换成什么词？候选——「生效于」「已启用」「归属」。需要同时改
中文与其余四种语言的文案。

### E2. 未安装的 Agent 不应显示 **[待决策范围]**

出现在两处：
- Agent 管理页：25 个 Agent 全列出来，其中只有 4 个已安装，其余标注「程序未安装」
- Skill 页的筛选标签：「已分发到 OpenClaw / Kimi Code / ZCode」等，这些都是
  「仅发现配置」而非已安装程序

**需要澄清**：「仅发现配置」指的是找到了该 Agent 的配置目录或 Skills 目录、
但没找到可执行程序。这类要不要显示？完全隐藏的话，用户可能不知道
「原来还支持这么多 Agent」。

**候选方案**：默认只显示已安装的，底部加一个「显示全部支持的 Agent」折叠区。

### E3. Skill 分类 **[利弊分析]**

维护者提议给 Skill 加分类，并特别提到区分「自定义」与「从 GitHub 拉取」。

**好处**：
- 42 个 Skill 平铺已经需要滚很久，会随时间继续增长
- 来源分类**几乎零成本**——数据已经存在（见 E4），只是没暴露成筛选条件

**代价 / 风险**：
- 手工分类需要用户维护，容易烂尾（新增 Skill 忘记归类）
- 分类维度选错会比不分类更乱（按用途分？按语言分？按来源分？）

**建议**：先只做**按来源自动分类**（自定义 / GitHub / 从 Agent 同步），因为它
不需要用户维护、数据现成。用途类的手工标签等实际感到不够用了再加。

### E4. 「0 个 GitHub 来源可检查」是什么意思 **[已查明]**

**不是功能坏了。** 这个数字统计的是「来源为 GitHub 的 Skill 有几个」
（判据：`sourceType === 'github'` 或来源地址含 `github.com`）。

你现在 42 个 Skill 全部显示「手动加入中心库」，没有一个是通过 GitHub 导入流程进来的，
所以计数为 0。计数为 0 时「检查更新」按钮会被**禁用**，因为没有可检查的对象。

**这直接支持 E3**：来源信息本来就存着，做来源分类只是把已有数据显示出来。
