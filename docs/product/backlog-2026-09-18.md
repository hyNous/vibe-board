## 0. 定位

多 Agent 的「**任务观察 + 额度观察 + 成本分析**」桌面看板。

- 核心是**看**，不是**操作**。在看板上批准、回答、与 Agent 对话不在范围内。
- **任何自动行为默认关闭**，由用户自己打开。

这一定位与 2026-08-29 原始 PRD（`00-PRD.md` 第 2 节）一致。以下两处是**有意推翻 PRD**：
Skill 管理保留（PRD 5.3 列为非目标）、审批操作删除（PRD 8.5 列为 MVP 快速操作）。

## 1. 删除

| 删除项 | 理由 |
| --- | --- |
| 审批框三类卡片（权限审批、计划确认、问题回答） | 推翻 PRD 8.5。权限提示在 Agent 已开自动审批时仍误报，会误报的操作入口是负资产 |
| 角色主题 / 展示形态 | 宠物系统残留。**已完成**（`97aef2f`） |
| MCP 管理、Plugin 管理 | PRD 5.3 非目标；约 5,600 行，独立产品的体量 |
| Agent「更新 / 安装」操作 | PRD 5.3 非目标「Agent 安装 / 升级」 |
| 技能包（含托盘技能包选择器） | 与「生效于」做同一件事，多一层「先分组再生效」的间接 |
| 宿主概念、宿主插件 `plugins/vibe-board-host` | 宿主只承担「拉起看板」「额度页头条」两件事，均改为中立做法；插件职责被 Hook 完全覆盖 |
| `agentctl` 与「任务追踪演示」 | 2026-08-31 的派发原型：前端未调用、未打包、本机 0 条记录。派发改为「搭建助手」后不再需要 |

**审批框删除的连带要求**：`PermissionRequest` 事件带 6 小时阻塞超时，`PreToolUse`
在「提问」工具与 Gemini / Antigravity 上也会阻塞等待看板回应。**只删界面不断开阻塞
链路，Agent 会挂起最长 6 小时。** 必须连同第 2 节的 Hook 改动一起做。

## 2. Agent 接入（Hook）

**事件瘦身**（Claude Code 原挂 14 个事件）：

| 处理 | 事件 |
| --- | --- |
| 删除 | `PermissionRequest`、`PermissionDenied`、`PostToolUseFailure`、`PreCompact`、`PostCompact` |
| 改造 | `PreToolUse`：删除阻塞分支，只上报「正在用什么工具」后立即返回 |
| 保留 | `SessionStart`、`SessionEnd`、`UserPromptSubmit`、`PostToolUse`、`Stop`、`Notification`、`SubagentStart`、`SubagentStop` |

删除后任务状态照常可读，只是不再等待审批。其它 Agent 的事件表按同一原则处理。

**不做设置页**：Hook 安装放进首次向导；平时只在灵动岛上留一个**出问题才亮**的健康
指示，点击展开自检（原「Hook 诊断」的六项检查）。

### 🐞 P0 缺陷：Claude Code 的 Hook 在 Windows 上全部静默失败

- 现象：bridge 调用记录共 48,642 条，Claude Code 仅 1 条（2026-09-06）。
- 根因：Hook 命令写成反斜杠路径 `C:\Users\...\vibe-board-bridge.exe`。Claude Code 在
  Windows 上用 bash 执行 Hook，bash 把 `\` 当转义符吃掉，得到
  `C:Users27312.vibeboardbin...`，退出码 127，无任何提示。
- 已验证修法：路径改为正斜杠 `C:/Users/...` 后 bash 正常执行并记录。
- 影响：所有装了 Git Bash 的 Windows 用户。**看板对 Claude Code 一直是瞎的。**
- 已安装用户需要在升级后重写一次 Hook 命令，否则旧的反斜杠命令仍在配置里。

### 🔍 待实测：Codex 事件几乎为零

Codex 仅 2 条记录（2026-09-06）。Hook 同为反斜杠路径，`[features] hooks = true` 已开，
信任记录存在。最可能原因是维护者主要使用 Codex 桌面版、桌面版不执行命令行 Hook；
看板上的 Codex 任务来自读取本地会话日志的另一条通道。**需开一个 Codex 命令行会话
实测确认。**

另：OpenCode 有 20,142 条、Antigravity 有 1,345 条事件因当时看板未运行而未送达。

## 5. Skill 管理（保留，推翻 PRD 5.3）

- 「分发」改称「**生效于**」，五种语言同步。
- 只显示已安装的 Agent，其余收进一个「+」按钮；「只找到配置目录、没找到程序」的

- 技能包删除（见第 1 节）。

## 6. 派发框架搭建（附加功能）

**定位**：只当**搭建助手**。搭完即撒手，此后派发不经过 Vibe Board。

- 已知工人（OpenCode、Antigravity）一键接入：检测 → 预览将写入的文件 → 确认后安装进
  用户的 Claude Code / Codex。
- 软件不认识的新工具：交回给 Agent 处理（运行 `external-agent-setup`）。
- 派发规则（何时派、派给谁）：用户自己写，软件**不改动**全局指令文件。
- 维护者的四个派发 Skill（`external-agent-core`、`external-agent-setup`、
  `opencode-agent`、`antigravity-agent`，均为本地自建）**收进仓库、随安装包分发**，
  适用 Apache-2.0。
- 依赖 Node.js：向导检测，缺失时提示。
- 复用第 5 节改好的 Agent 检测与 Skill 链接能力，因此**排在 Skill 管理之后**。

现成基础：`external-agent-setup/scripts/setup-agent.mjs` 已提供
`--detect` / `--plan` / `--apply --confirm` 三段接口与已知工人目录。

## 7. 使用额度（记录仪表盘）

**回答两个问题：还剩多少、花了多少。** 这是回归 PRD（第 2 节定位含「成本分析」，
5.1 MVP 含 Usage History，11.4 节规定了成本口径），**不是**定位改变。README 中
「不生成价格估算」一句才是早先的偏离。

- 页面分上下两块：「现在」（各 Provider 剩余额度、重置时间）+「用量与成本」
  （今天 / 本周 / 本月）。
- 成本只做**等价成本**（按公开单价折算），一律标 `Estimated`。
- 取数：用户**逐个 Provider 授权**后，用其本地凭据调官方接口；说明会发出什么请求；
  可随时撤销。默认不授权。
- 历史：从 Agent 自己写的会话日志回溯（本机 Codex 654 个日志，覆盖 2026-05-06 起），
  **无需常开软件**。单个日志可达 176 MB，必须增量扫描（按路径 + 大小 + 修改时间缓存）。
- 统计：本地时区、零点切分、按天汇总后永久保存（防止 Agent 清理旧日志后历史丢失）；
  周、月结算在日汇总上加总。
- 后端参考 OpenUsage：每个 Provider 统一为「读凭据 → 取数 → 归一化」三段，产出同一种
  快照结构。
- **功能落地时**同步修改 README（中英）能力表与 `docs/privacy-policy.md`；落地前不改。
